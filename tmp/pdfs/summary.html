  • สมาชิก: เติม Wallet ซื้อบัญชีเกม สุ่มรางวัล เปิดประวัติและคลังของตน อ่านแจ้งเตือน เปลี่ยนรหัสผ่าน และสนทนากับร้าน
  • ผู้ดูแล: จัดการสมาชิก หมวดหมู่ บัญชีเกม กล่องสุ่ม ตรวจเติมเงิน ดูรายงาน ตอบข้อความ และตั้งค่าร้าน/แบนเนอร์
  • config/store.php กำหนด service_catalog_enabled=false และ demo_mode=true: ระบบสินค้า/งานบริการมีโครงสร้างรองรับ แต่ปิดทางเข้าใช้งานที่เกี่ยวข้องอยู่

Wallet และการตรวจเติมเงิน

เพิ่มเครดิตเมื่ออนุมัติ พร้อมป้องกันคำขอและหลักฐานซ้ำหลายชั้น

  • หน้า Wallet รองรับช่องทาง PromptPay และ TrueMoney ตามขั้นตอนส่งหลักฐานให้ผู้ดูแลตรวจ ยังไม่ใช่การยืนยันเงินเข้าอัตโนมัติจากผู้ให้บริการ
  • รายการใหม่อยู่สถานะ pending; การอนุมัติจึงเพิ่มเครดิต ส่วนการปฏิเสธต้องมีเหตุผลและไม่เพิ่มยอด
  • ใช้ request_id และ fingerprint เพื่อให้การส่งคำขอเดิมซ้ำคืนรายการเดิม และปฏิเสธเมื่อใช้รหัสเดิมกับข้อมูลที่เปลี่ยน
  • มี hash ไฟล์สลิปและการจองเลขอ้างอิงการโอนตามช่องทาง เพื่อป้องกันการใช้ซ้ำตามเงื่อนไขระบบ
  • เก็บผู้ตรวจ เวลา สถานะก่อน/หลัง และเหตุผล สลิปรับ JPG/PNG/WEBP ขนาดไม่เกิน 5 MB
บันทึกผู้พูด

กลไกกันซ้ำช่วยรักษาความถูกต้องของรายการ แต่ไม่พิสูจน์ว่าเงินเข้าจริง ผู้ดูแลยังต้องตรวจยอดรับจากแหล่งที่เชื่อถือได้ ประวัติการตรวจไม่ใช่ audit log ครอบคลุมทั้งร้าน

การซื้อและส่งมอบบัญชีเกม

ผูกการตัดเครดิตกับการขายสินค้าในธุรกรรมเดียว

  • StoreService ตรวจยอด Wallet สถานะ available และประวัติว่าบัญชีนั้นยังไม่เคยถูกขาย
  • ใช้ database transaction และ lockForUpdate กับแถวผู้ใช้และบัญชีเกม เพื่อลดปัญหาคำขอซื้อชนกัน
  • เมื่อสำเร็จ สร้างประวัติซื้อ ตัดเครดิต เปลี่ยนสินค้าเป็น sold และบันทึก WalletTransaction
  • ข้อมูลบัญชีเกมและสำเนาข้อมูลส่งมอบถูกเข้ารหัส ผู้ซื้อเปิดข้อมูลได้จากเส้นทางที่ตรวจสิทธิ์
  • มีการป้องกันนำบัญชีที่มีประวัติขายแล้วกลับมาเปิดขาย และแจ้งเตือนผู้ซื้อ/ผู้ดูแลเมื่อเกิดรายการ
บันทึกผู้พูด

อธิบาย transaction ว่าเป็นชุดงานที่ต้องสำเร็จร่วมกัน หากขั้นตอนล้มเหลวจะย้อนการเปลี่ยนแปลงในฐานข้อมูล ไม่กล่าวอ้างว่าการเข้ารหัสป้องกันการเข้าถึงได้ทุกกรณี

ระบบสุ่มรางวัล Gacha

สุ่มจากรางวัลที่ยังมีสิทธิ์ออก และเก็บผลสำหรับคำขอเดิม

  • มีรูปแบบนำเสนอ cards / wheel / box โดยผลรางวัลคำนวณที่ฝั่งเซิร์ฟเวอร์
  • รางวัลเป็นเครดิต Wallet หรือบัญชีเกมที่ยัง available; คัดเฉพาะรายการที่มี drop_rate มากกว่า 0
  • โอกาสออกคิดจากน้ำหนักของรางวัลเทียบผลรวมน้ำหนักที่ใช้ได้ ณ เวลาสุ่ม จึงเปลี่ยนได้เมื่อชุดรางวัลเปลี่ยน
  • request_id ช่วยคืนผลสุ่มเดิมเมื่อส่งซ้ำ โดยไม่หักค่าสุ่มหรือจ่ายรางวัลซ้ำ; มี receipt และประวัติการสุ่ม
  • เมื่อได้บัญชีเกม ระบบอาจเติมรางวัลทดแทนจากหมวดเดียวกันหากมีบัญชีที่เข้าเงื่อนไข พร้อมรักษารายการเดิมเพื่ออ้างอิงประวัติ

ความถูกต้องและความปลอดภัย

ตรวจสิทธิ์ ป้องกันรายการซ้ำ และรักษาข้อมูลสำคัญ

  • เส้นทางสมาชิกตรวจ auth และ auth.session; หลังบ้านตรวจสิทธิ์ admin เพิ่ม และมี rate limit ในคำขอสำคัญ
  • ใช้ transaction, row locks และ unique constraints ร่วมกับ request identity เพื่อลดการขายซ้ำ เพิ่มเครดิตซ้ำ และสุ่มซ้ำ
  • เข้ารหัสข้อมูลบัญชีเกม/ข้อมูลส่งมอบ และจำกัดการเปิดสลิปกับภาพแนบส่วนตัวตามสิทธิ์
  • มี security headers และ CSP ตามรายงานแก้ไขล่าสุด แต่ยังใช้ unsafe-inline จึงไม่ใช่ strict CSP
  • การเปลี่ยนรหัสผ่านเกี่ยวข้องกับการหมดสิทธิ์ session เก่าผ่าน auth.session เมื่อมีการเรียกเส้นทางที่ตรวจ ไม่ได้หมายถึงลบ session ทุกเครื่องทันที
