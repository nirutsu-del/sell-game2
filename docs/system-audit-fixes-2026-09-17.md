# ผลแก้ไขจากการตรวจระบบ 17 กันยายน 2026

อัปเดต: ซ่อมฐานข้อมูล XAMPP และตรวจ concurrency/restore ผ่านแล้ว ดู [รายงานซ่อมและผลทดสอบล่าสุด](xampp-recovery-2026-09-17.md) ส่วนข้อจำกัด MariaDB ด้านล่างเป็นบันทึกสถานะก่อนการซ่อมรอบนี้

## แก้แล้วและใช้ migration บนเครื่องนี้แล้ว

1. กันเลขโอนซ้ำด้วย primary key ใน `topup_transfer_references` ภายใน transaction เดียวกับการเพิ่มเครดิต โดยคิดตัวตนจากช่องทาง + เลขอ้างอิงที่ trim และไม่แยกตัวพิมพ์ใหญ่เล็ก ป้องกันข้ามผู้ใช้ในช่องทางเดียวกัน หากขั้นตอนถัดไปล้มเหลว การจองเลขและเครดิตย้อนกลับพร้อมกัน
2. Backend บังคับสลิปทั้ง PromptPay/TrueMoney เป็น JPG/PNG/WEBP ไม่เกิน 5 MB ให้ตรงกับหน้าเว็บ
3. ส่ง receipt กาชาเดิมได้หลังกล่องถูกลบ พร้อม next_rewards ว่าง; HTML redirect ไป collection พร้อมข้อความผลเดิม การสุ่มใหม่บนกล่องที่ลบแล้วยังถูกปฏิเสธ

Migration นำเลขโอนจากรายการ success เดิมมาจองด้วย หากข้อมูลเก่าเคยมีเลขซ้ำจะเก็บประวัติไว้ทั้งหมดและจองเลขครั้งเดียว ไม่มีการปรับยอดย้อนหลัง ขณะใช้ migration บนเครื่องนี้ไม่พบเลขเก่าที่นำมาจองได้ (0 rows)

## ปัญหาโครงสร้างพื้นฐานที่ยังต้องติดตาม

MariaDB 10.4.32 บนเครื่องหยุดระหว่างสร้าง schema ทดสอบแยก โดยรายงาน connection refused หลังจากเชื่อมต่อเริ่มต้นได้ ต่อมาสตาร์ตกลับและสำรองข้อมูลสำเร็จ แต่คำสั่งลบ schema ทดสอบค้างใน Closing tables พร้อม CPU สูง ส่งผลให้การอ่านตาราง migrations ค้างด้วย ยังไม่ได้ยืนยันสาเหตุรากของอาการนี้

ได้พยายามหยุดคำสั่งของงานนี้และ shutdown ตามปกติ แต่โปรเซสยังค้าง จึงหยุดโปรเซสที่งานนี้เปิดแล้วสตาร์ตกลับด้วย my.ini เดิม หลังจากนั้น migration และหน้าเว็บทำงานสำเร็จ ไม่ได้แก้หรือลบไฟล์ InnoDB ของร้านโดยตรง
