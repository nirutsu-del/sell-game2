# ประวัติการตรวจเติมเงินและเหตุผลปฏิเสธ

อัปเดต 8 กันยายน 2026

- หน้าแอดมินตรวจเติมเงินมีลิงก์ “ประวัติการอนุมัติ / ปฏิเสธ” ไป /admin/topups/history ค้นด้วยเลขอ้างอิงตรงกันทั้งหมดและกรองการดำเนินการได้ แบ่งหน้า 30 รายการ
- ประวัติเก็บผู้ดำเนินการ (ID และชื่อ ณ ตอนทำรายการ) เลขอ้างอิง ยอด สถานะก่อน/หลัง เหตุผล และเวลา แสดงเวลา Asia/Bangkok
- ปฏิเสธต้องระบุเหตุผล 5–500 ตัวอักษร ข้อความจะแสดงให้ลูกค้าในหน้า Wallet เฉพาะรายการของตัวเองและการแจ้งเตือน ห้ามใส่ข้อมูลลับหรือข้อมูลบุคคลอื่น
- การอนุมัติ/ปฏิเสธ ประวัติ และ notification อยู่ใน transaction เดียวกัน หากบันทึกไม่ครบจะ rollback รวมถึงยอด Wallet unique topup_id และการล็อกสถานะป้องกันบันทึกผลตัดสินซ้ำ
- ประวัติใหม่นับตั้งแต่อัปเดตนี้ ไม่สร้างผู้ตรวจหรือเหตุผลย้อนหลังให้รายการเก่าที่ไม่มีหลักฐาน ไม่มี route ให้แก้/ลบประวัติ แต่ไม่ได้เป็นระบบ log ป้องกันการแก้ไขระดับฐานข้อมูล ผู้ดูแล DB ยังแก้ไขได้
- ตารางประวัติจำกัดการลบรายการเติมเงินที่เชื่อมอยู่เพื่อรักษาหลักฐาน จึงอาจจำกัดการลบผู้ใช้ที่มีประวัติด้วย ต้องกำหนดนโยบายเก็บข้อมูลก่อนเพิ่มฟังก์ชันลบบัญชี
