# ทดสอบการซื้อครบวงจร — 8 กันยายน 2026

เพิ่ม StoreJourneyTest สำหรับ HTTP integration ของ Laravel ใช้ SQLite :memory: ตาม phpunit.xml และ Storage::fake('local') ไม่เขียนรายการลง MySQL ร้าน ไม่ใช้สลิปจริง ไม่เรียกผู้ให้บริการชำระเงิน และไม่ส่งอีเมล

## เส้นทางที่ทดสอบ

1. เปิดหน้าสินค้าโดยไม่เห็นรหัสลับ สมัครสมาชิกผ่าน route จริง ได้ role ผู้ใช้และ Wallet 0 แม้ส่ง role/balance ปลอม
2. ซื้อก่อนมีเครดิตถูกปฏิเสธ ส่งรายการเติมเงิน 300 บาททดสอบพร้อม PNG จำลอง สถานะ pending ยังไม่เพิ่มยอด
3. ผู้ซื้ออนุมัติรายการเองหรือเปิดสลิปผ่าน route แอดมินไม่ได้
4. ออกจากระบบแล้ว login แอดมินผ่าน route จริง เปิดรายการและสลิป อนุมัติได้ครั้งเดียว เครดิตเพิ่มเป็น 300
5. ออกจากระบบแล้ว login ผู้ซื้อ ซื้อไอดี 199 ได้รับข้อมูลจากหน้าส่งมอบ ยอดเหลือ 101 สินค้า sold และมีการแจ้งเตือน
6. ซื้อซ้ำไม่หักเครดิตซ้ำ ข้อมูลส่งมอบที่เก็บในฐานข้อมูลไม่เป็น plaintext ผู้ใช้อื่นและ guest เปิดหน้ารับข้อมูลไม่ได้
7. ทำเส้นทางเดียวกันทั้ง promptpay_slip และ truemoney_gift ตามรูปแบบตรวจสอบด้วยแอดมินในระบบปัจจุบัน ไม่ใช่การทดสอบ API ของผู้ให้บริการ
8. แยกกรณีปฏิเสธเติมเงิน: ยอดไม่เพิ่ม อนุมัติภายหลังไม่ได้ และซื้อไม่ได้

รันซ้ำ: `php artisan test --compact --filter=StoreJourneyTest`

## ข้อจำกัดและขั้นตอนต่อไป

นี่คือ integration test ในเครื่อง **ไม่ใช่ staging ที่ deploy แล้วหรือ browser E2E** Laravel test harness ไม่เปิด JavaScript และปิด CSRF middleware ตามค่าเริ่มต้น จึงยังไม่ตรวจภาพ QR จริง การกดปุ่มบนมือถือ cookie/CSRF ผ่าน browser และการแข่งขันซื้อพร้อมกันบน MySQL

ขั้นถัดไปคือสร้าง staging แยกจาก production โดยใช้ฐานข้อมูลและข้อมูลสินค้าจำลองเท่านั้น จากนั้นตรวจ browser flow บน desktop/mobile, CSRF, HTTPS และการซื้อพร้อมกัน ห้ามตั้ง URL/บัญชีชำระเงินจริงใน staging ต้องมีข้อมูลโฮสต์หรือเลือกใช้ staging บนเครื่องก่อน จึงยังไม่เผยแพร่เว็บไซต์หรือเพิ่มบริการที่มีค่าใช้จ่าย
