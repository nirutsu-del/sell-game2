# ตรวจไฟล์สลิปซ้ำและอนุมัติด้วยผู้ดูแล

อัปเดต 8 กันยายน 2026: ใช้ SHA-256 ของไฟล์กับ primary key ใน topup_slip_hashes ป้องกันไฟล์เดียวกันถูกส่งด้วย request_id ใหม่ รวมข้ามผู้ใช้ โดยข้อความปฏิเสธไม่เปิดเผยข้อมูลเจ้าของเดิม คำขอเดิมที่ส่งซ้ำยังคืนรายการเดิมตาม idempotency ไม่เพิ่มไฟล์หรือ notification

รายการที่ปฏิเสธแล้วก็ยังสงวน fingerprint ไว้ หากต้องการแก้ไขให้ติดต่อร้าน ไม่ลบหลักฐานเดิมอัตโนมัติ การตรวจนี้ไม่ได้ใช้แทนการตรวจยอดเงินจริง และไม่ได้จับภาพที่ครอป บีบอัด หรือแก้ไข หรือการนำเลขอ้างอิงเดียวกันไปกรอกหลายรายการ

หน้าแอดมินต้องกรอกยอดเข้าจริงให้ตรงยอดแจ้ง เลขอ้างอิงจากบัญชีรับเงิน และยืนยันว่าตรวจบัญชีรับเงิน/ยอด/เลขอ้างอิงแล้ว ฝั่งเซิร์ฟเวอร์บังคับด้วย ไม่เติมยอดล่วงหน้า การอนุมัติเก็บ reviewer_id, reviewed_at, received_amount และ transfer_reference ใน verification_payload เป็นหลักฐานการตรวจด้วยคน ไม่ใช่ผลยืนยันจากธนาคาร

รายการไม่มีสลิปยังอยู่ในระบบได้เพื่อรองรับรายการเดิม แต่แอดมินต้องตรวจรายการเข้าจริงและกรอกหลักฐานเช่นเดียวกัน การอัปโหลดสลิปและการติ๊กยืนยันอย่างเดียวไม่ได้พิสูจน์การโอน

สำรองก่อน migration: store_20260908_004449_fbaa5ca6e890 จากนั้น migrate และรัน `php artisan store:index-slips` เพื่อทำดัชนีไฟล์เก่า พบ 1 ไฟล์ ไม่มีไฟล์หายหรือซ้ำในข้อมูลที่ตรวจ ไม่เปลี่ยนสถานะ/เครดิตของรายการเดิม คำสั่งรันซ้ำได้และแจ้งเตือนเมื่อมีไฟล์หายหรือประวัติซ้ำให้ผู้ดูแลตรวจเอง

staging ใช้ `php scripts/staging-migrate.php` แล้ว `php scripts/staging-index-slips.php`

ผล: 59 tests / 534 assertions ผ่าน และ Vite build สำเร็จ ทดสอบไฟล์ซ้ำข้ามบัญชี, index ซ้ำ, ยอดไม่ตรง, ไม่มีคำยืนยัน/เลขอ้างอิง, rollback และ idempotency เดิม ไม่ได้อนุมัติเงินจริงระหว่างทดสอบ ยังไม่ได้ทดสอบโหลดพร้อมกันบน MySQL จริง
