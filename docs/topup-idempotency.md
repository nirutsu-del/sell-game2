# ป้องกันส่งรายการเติมเงินซ้ำ — 8 กันยายน 2026

ฟอร์มใหม่ส่ง request_id แบบ UUID ทุกครั้งที่เปิดฟอร์มใหม่ เซิร์ฟเวอร์ล็อกแถวผู้ใช้ใน transaction และมี unique index (user_id, request_id) คำขอเดิมที่ข้อมูลตรงกันจะคืนรายการเดิม ไม่บันทึกไฟล์หรือแจ้งเตือนแอดมินซ้ำ แม้รายการนั้นอนุมัติแล้ว

Fingerprint ประกอบด้วยจำนวนเงิน 2 ตำแหน่ง ช่องทาง และ SHA-256 ของไฟล์สลิป ถ้าใช้ request_id เดิมแต่เปลี่ยนข้อมูลจะปฏิเสธคำขอ ห้ามแก้ไขรายการเดิมโดยเงียบ

หลังส่งสำเร็จ redirect 303 ไป /wallet?topup=ID แสดงเลขอ้างอิง จำนวน และสถานะที่อ่านจากฐานข้อมูล ไม่แสดงฟอร์มเดิมซ้ำ เจ้าของเท่านั้นที่เปิดได้ มีปุ่มเริ่มรายการใหม่ ฟอร์มมีสถานะกำลังส่งและล็อกปุ่มชั่วคราว คืนปุ่มเมื่อกลับมาจาก browser history
